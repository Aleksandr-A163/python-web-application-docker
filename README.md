# Телефонный справочник в Docker

Этот репозиторий содержит Docker-сборку веб-приложения.
Описание приложения, его возможностей, API и архитектуры находится в
[исходном репозитории python-web-application](https://github.com/Aleksandr-A163/python-web-application).

## Требования

Для сборки и запуска нужен работающий Docker с поддержкой Linux-контейнеров
(например, Docker Desktop). Python и зависимости устанавливаются внутри образа.

## Сборка образа

Клонируйте репозиторий и выполните сборку из его корня:

```bash
git clone https://github.com/Aleksandr-A163/python-web-application-docker.git
cd python-web-application-docker
docker build -t python-web-application-docker .
```

Dockerfile использует базовый образ `python:3.12-slim` и три этапа:

1. `base`: копирует `requirements.txt` и устанавливает зависимости отдельным
   слоем, затем копирует всё приложение, включая модули, шаблоны и статику.
2. `test`: устанавливает зависимости разработки и запускает тесты.
3. `runtime`: использует основные зависимости и запускает приложение от
   непривилегированного пользователя. Установленные тестовые зависимости
   в итоговый образ не попадают.

Обычная сборка образа требует успешного завершения этапа `test`.
Файл `.dockerignore` исключает из контекста сборки Git, локальные виртуальные
окружения, кэши и файлы `.env`.

## Запуск контейнера

```bash
docker run --rm --name phonebook-web -p 8000:8000 python-web-application-docker
```

Сервер запускается командой:

```bash
uvicorn app:app --host 0.0.0.0 --port 8000
```

В Dockerfile объявлен `EXPOSE 8000`. Параметр `-p 8000:8000` связывает порт
8000 компьютера с портом 8000 контейнера.

Откройте приложение: [http://localhost:8000/](http://localhost:8000/).
Для остановки нажмите `Ctrl+C` в терминале с контейнером.
Флаг `--rm` удалит контейнер после остановки; собранный образ останется.

## Проверка доступности

После запуска откройте [http://localhost:8000/ping/](http://localhost:8000/ping/).

Маршрут `GET /ping/` возвращает статус `200 OK` и JSON:

```json
{"message": "pong"}
```

## Тесты при сборке

Этап `test` запускает весь набор тестов с `-W error` и требованием покрытия
пакета `phonebook` на 100%. Ошибка теста, предупреждение или недостаточное
покрытие останавливают сборку.

Для сборки только тестового этапа:

```bash
docker build --target test -t python-web-application-docker:test .
```

GitHub Actions при каждом push и pull request собирает образ, запускает
контейнер и проверяет статус и тело ответа `/ping/`.
Образ автоматически не публикуется в Docker Hub.

## Данные контейнера

Контейнер начинает работу с `contacts.json` из репозитория. Изменения хранятся
внутри контейнера и при его удалении теряются. Для постоянного хранения
можно подключить существующий файл с правами записи через bind mount
по пути `/app/contacts.json`.
